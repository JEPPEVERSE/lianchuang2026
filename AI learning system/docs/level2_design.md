# Level 2 设计与验收

## 数据流

```text
Markdown → 精确原文切分 → Analysis Agent → Schema/引用校验
→ 名称与别名匹配/已有 ID 选择 → SQLite 事务 → 全图环检测 → 发布

问题 → BM25/别名匹配 → 一跳图扩展 → 带来源的 RetrievalResult
→ QA Agent → 引用与状态校验 → 回答/资料不足 → SQLite 问答快照
```

存储与执行由 Python 控制，模型只提出结构化分析结果或回答。
使用 SQLite 作为原文、知识点、题型关联与问答记录的权威存储；向量库不属于最小版本。

## 工件与来源

- Document：绝对路径、类型、全文、SHA-256 和入库时间。以路径作为当前导入身份。
- Chunk：稳定 ID、原文件行号、小节标题、精确正文。默认按小节和段落切分。
- Point：后端生成 ID、标准名称及唯一别名映射。
- Prerequisite：前置/后续 ID 与支持片段 ID；它只是学习依赖，不是所有数学事实关系。
- Problem：模型提取的题号、题型、连续原文、来源片段与知识点关联。
- RetrievalResult：问题、起始/扩展知识点、片段正文、来源 hash、排序分数和命中原因。
- AnswerArtifact：answered/partial/insufficient、正文、原文摘录及缺失内容。
- QARecord：完整检索及回答快照、时间与轻量状态；后续查询不会改写既有快照。

引文行号定位整个片段，quote 给出片段内的精确摘录。引用对应入库时的原文快照，
不声称磁盘文件在问答时仍与快照相同；content_hash 可用于识别来源版本。

## 分析与更新边界

资料和真题使用同一个 Analysis Agent 的不同类型约束。资料不产生题目，真题不产生前置边。
原始 Markdown 中的示例不是独立题库项。显式 Q1/LA-Q001 类题号必须完整提取。

同名/别名精确匹配优先；模型仅能选择已提供的知识点 ID，且置信度至少 0.85 时
才使用语义匹配结果。否则保留新节点。别名冲突到多个节点则整份文件拒绝入库。
这不是经过概率校准的置信度，仍需人工检查知识点质量。

格式或来源引用错误允许一次纠正调用；传输失败、循环依赖或最终别名冲突直接报告。
每份文件独立发布：同路径同 hash 重复导入跳过模型；改动或改类型拒绝覆盖。
目录第 N 份失败时，第 1 到 N−1 份成功资料仍然保留，失败文件没有部分状态。
事务前完成模型调用，避免等待网络期间占用 SQLite 写锁。

## 检索范围

只检索 resource 原文；题目仍可通过知识点查询，但不作为回答定理的权威证据。
词法采用中文二元片段、部分数学单字与英文词的 BM25，加上标题与别名信号。
从前三个直接命中片段及别名知识点出发，沿前置边双向扩展一跳。
同一知识点关联的其他片段也能被召回。最多保留 8 个片段、12000 个原文字符，均可配置。
存在扩展证据时最多预留两个位置；直接证据在展示顺序上优先。

此机制受图检索思路启发，没有 embedding、PPR 或 OpenIE 全事实图，不能称为完整 HippoRAG。
单纯词法检索可能无法命中关键词完全不同的同义问题，别名只能弥补部分情况。

## 可靠问答的实际保证

后端确定性检查 Schema、所引用 ID 是否属于本次检索、摘录是否真实存在以及回答状态是否合法。
检索为空则不调用模型，直接记录资料不足。模型服务失败时不会回退到无证据回答。
partial/insufficient 必须说明缺失内容；answered/partial 必须提供引用。

这些措施保证引用的真实性，不能完整证明所有回答结论都由引文蕴含，也不能自动证明数学正确。
模型会被要求检查关键条件、错误前提与证据充分性；最终质量应通过实际模型的评估样例验证。

## 成本与限制

每个分析批次默认最多 3000 原文字符，可通过 LLM_ANALYSIS_BATCH_CHARS 设置。
DeepSeek 默认显式关闭思考，分析/问答分别设置输出预算，stderr 记录耗时与 token 统计。
格式不合法可能再调用一次；因输出上限截断时不重复相同请求。
有证据的每次问答一调用，最多一次纠正；不在传输超时后自动重试，以避免重复费用。
已成功入库的相同文件零分析调用。建议先用 --limit 2 验证服务，再导入全部资料。
单文件上限 2 MB；不跨行号破坏性截断长代码块，超过批次预算的单个不可拆段落会要求拆分。

最小版不更新学生掌握度、不作个性化排序、不支持资料删除/替换，也不提供完整多轮上下文。
QA 的 history 与 state 是后续 Level 3 的基础记录，不是已验证的学生模型。

## 验证层次

测试包含真实 SQLite、文件系统与本地 HTTP 传输，模型输出使用明确的测试 fixture。
它们验证格式、事务、来源和状态等机制，不代表真实 DeepSeek 已达到检索/回答质量要求。
使用 data/linear_algebra/evaluation_queries.json 手工核查跨章节、反例和缺失资料问题。
solutions/ 与评估文件不应导入课程事实库；文件 kind=solution 时后端也会拒绝。
